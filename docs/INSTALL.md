# Installation

## Prerequisites

- Python ≥ 3.11
- `pip` ≥ 23
- On Linux x86_64 with an NVIDIA GPU: recent CUDA drivers if the `gpu` extra is installed.

## Steps

```bash
git clone https://github.com/benoit-bremaud/aristech.git
cd aristech
python -m venv .venv
source .venv/bin/activate            # Linux/macOS
# .\.venv\Scripts\activate           # Windows
pip install -e ".[dev,vision]"
mise install                         # local CI tools (mise.toml)
mise x -- lefthook install           # git hooks: just fast on commit, just check on push
```

### Extras

- `vision` — torch, torchvision, OpenCV, pandas, Pillow: the live detector and the evaluation
  runner. Version floors follow the security advisories (ADR-0012); `numpy<2` and
  `opencv-python<5` are held on purpose.
- `dev` — pytest, ruff, mypy, pip-tools. The local CI tools (just, lefthook, gitleaks, semgrep,
  osv-scanner, typos, actionlint, zizmor) come from `mise.toml` (ADR-0027); mise needs `uv` to
  install mypy and Semgrep.
- `gpu` — NVIDIA CUDA libraries (Linux x86_64 only).

```bash
pip install -e ".[dev,vision,gpu]"     # Linux GPU target
```

### VespAI weights and YOLOv5

The live detector and the integration test need two operator-supplied inputs, never committed
(VespAI weights are CC BY-NC-SA, ADR-0002):

- the weights: a YOLOv5s checkpoint from
  [andrw3000/vespai](https://github.com/andrw3000/vespai), `models/yolov5-params/`
  (e.g. `yolov5s-all-data.pt`);
- the YOLOv5 code at the commit VespAI pins as its `models/yolov5` submodule
  (`23701eac7a7b160e478ba4bbef966d0af9348251` of
  [ultralytics/yolov5](https://github.com/ultralytics/yolov5)).

That YOLOv5 commit imports `pkg_resources`, so the environment also needs `setuptools<81`, plus
YOLOv5's own runtime packages (`matplotlib`, `scipy`, `seaborn`, `tqdm`, `requests`, `psutil`):

```bash
pip install "setuptools<81" matplotlib scipy seaborn tqdm requests psutil
```

A training environment with the `train` extra also needs a `typing_extensions` newer than the one
in `requirements.txt` (rfdetr's dependencies import `typing_extensions.Sentinel`):
`pip install -U typing_extensions`.

The checkpoint is a pickle: torch ≥ 2.6 refuses it by default, and `VespAIDetector` loads it with
`weights_only=False` because it comes from a trusted path. Never point `--weights` at an untrusted
file.

## Capture rig (C1, Raspberry Pi 5)

On Raspberry Pi OS (Bookworm or later), with the I²S overlay for the two ICS-43434 enabled in
`/boot/firmware/config.txt` (ADR-0017):

```bash
sudo apt install python3-picamera2 libportaudio2 libsndfile1
python3 -m venv --system-site-packages .venv
.venv/bin/pip install -e ".[capture]"
.venv/bin/aristech-record --rig-id rig-1 --hive-id hive-a --site home \
  --latitude 48.85 --longitude 2.35 --output /mnt/ssd/segments --software-version "$(git rev-parse --short HEAD)"
```

Picamera2 comes from apt (it needs the system libcamera), hence `--system-site-packages`.

## Dataset registry (annotation pipeline)

Stdlib only, no extra needed (spec `docs/architecture/specs/annotation-pipeline.md`,
ADR-0018 to ADR-0020). `data/registry/` (licence register, manifest, frozen test sets) is
committed; images and canonical labels go to the git-ignored `data/dataset/`.

```bash
# 1. Add the source to data/registry/licences.csv (allowed: CC-BY-4.0, CC-BY-SA-4.0, CC0-1.0, own).
# 2. Download its YOLO export under data/external/<source>/, then import with a class map
#    (source id:canonical id; canonical 0 velutina, 1 crabro, 2 apis_mellifera, 3 other):
python scripts/dataset.py import --source roboflow-hornet-behavior-v1 \
    --dir data/external/vespa-crabro-velutina --class-map 0:1,1:0
# 3. Split by group (deterministic; every frozen data/registry/test-v*.csv is enforced):
python scripts/dataset.py split --seed 0
# 4. Freeze the test rows once (never rewritten; a label fix means a new version):
python scripts/dataset.py freeze --id test-v1
```

Exit code 2: licence not allowed, unmapped class, frozen-set violation, version already frozen.

## Configuration

Two YAML files drive the application:

- [`config/config.yaml`](../config/config.yaml) — application settings.
- [`config/logging.yaml`](../config/logging.yaml) — logging.

The CLI loads `config/config.yaml` by default; another path can be passed:

```bash
aristech --config /path/to/my-config.yaml
```

### Environment variables

`.env` (not versioned, see [`.env.example`](../.env.example)) holds the dataset paths for the split
scripts and the VespAI paths for the integration test. The live CLI needs no `.env`: weights and
video are passed as flags.

## Lock reproducibility

`requirements.in` lists the top-level dependencies. `requirements.txt` is a lock generated by
`uv pip compile` for Python 3.11, the lowest supported version (ADR-0026); regenerate it with:

```bash
make lock
```

Do **not** paste a raw `pip freeze`: it would include the machine-specific CUDA libraries, which
belong in the `gpu` extra.

## Check

```bash
make test-unit
aristech --help
```

If `aristech --help` prints the usage, the install is good.
